# OSS Skills (placeholder)

Add skills here only when they capture something project-specific and reusable — e.g. "how release-drafter is configured in repo X", not generic "how to write a good commit message."

If a skill would apply to any OSS repo you maintain regardless of specifics, it probably belongs in the global `skills/` directory instead — this directory is for OSS-domain knowledge that isn't universal engineering practice (which is already better covered by `agents/` role prompts).
